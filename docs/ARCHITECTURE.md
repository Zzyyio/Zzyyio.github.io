# 实现架构

## 分层

```text
Semantic DOM
├── app/page.tsx
├── app/photography/page.tsx
└── app/projects/page.tsx
        │
Persistent frame
├── fixed navigation
├── route detection
├── SVG line field
└── WebGL ripple canvas
        │
Visual data
└── normalized route shapes
```

页面内容由服务端组件输出。`PortfolioFrame` 是客户端持久层，读取当前路径并驱动背景线与 WebGL 波纹。路由变更时，页面内容更新，视觉层保持同一套组件生命周期。

## 黑线

`lib/visual-shapes.ts` 为每个路由保存相同数量的归一化控制点，并根据全页滚动进度添加围绕中心约 `0.12` 个视口的小幅纵向往返、局部弯折、横向剪切与一次相位扭转，使页面顶部、中段和底部的线条轮廓清楚不同但不持续漂离画面。章节构图另由离散的 `sectionIndex` 驱动：`LineField` 读取语义区块的位置，当视口中心越过下一条分割线时才更新索引。每个构图为首尾端点指定新的屏外锚点，其他控制点依据到两端的距离接收不同权重的位移，再叠加小幅弧度；不对整条曲线做镜像。端点变形后，以正弦包络对内部控制点做有限的中心校正，使内部点群的平均位置维持在视口中央附近，而不移动两个端点。最终沿首尾相邻线段的方向外推端点，直到越过归一化视口至少 `0.16`，确保线帽不进入画面。

`LineField` 使用基于帧时间的阻尼从当前构图追向新的离散目标。端点响应较快，中段较慢，形成端点滑移并牵动整条线的二维动画；即使滚动停下，`requestAnimationFrame` 仍会让动画自行完成。主线完成后，回声线采用更长的阻尼时间继续跟随。滚动监听只读且为 passive，不写入滚动位置，不调用 `preventDefault`。

端点越界约束还要在每帧插值完成后再次执行，因为两个都在视口外的目标端点相互插值时，中间状态仍可能穿回视口。初始 SVG 路径也必须使用已经外推的形状，避免首帧闪现端点。

渲染后的曲线会被均匀采样，并通过 `lib/line-runtime.ts` 暴露给 WebGL 模拟。这样波纹始终吸向屏幕上实际可见、已经响应滚动的曲线，而不是静态控制点。

路径渲染采用连续二次样条：内部控制点作为二次 Bézier 控制点，相邻控制点的中点作为段落连接点。连接处切线连续，且曲线不会像自由三次样条那样在急剧位移时过冲或形成反折。`sampleSmoothCurve` 使用完全相同的二次公式采样，确保点波纹吸向屏幕上实际绘制的线。

控制点数量必须保持一致，否则不能直接逐点插值。新增路线时先定义形状，再将路线加入导航和路径解析。

常用黑线视觉参数入口记录在 `docs/VISUAL_TUNING.md`。

## WebGL 波纹

`RippleField` 使用 WebGL2 `LINES` 渲染透明细线束：

1. 桌面端每次有效 `pointermove` 都计算切向量与法向量，无需按下；触屏只在明确接触移动时反馈。
2. 创建一对只有起点的活动尾迹；鼠标每前进约 7px，才在尖端追加一个新节点，因此曲线随移动逐段生长。
3. 新节点位于鼠标头部附近；较早节点保留各自生成时的法线方向并缓慢向外漂移，使两条尾迹像船尾水纹一样自然打开。
4. 尾迹达到 12 个节点或鼠标停顿约 200ms 后释放，不再继续追加。
5. 在线上寻找最近采样点，为释放后的节点分配沿曲线有序排列的目标点，再逐帧增加吸引力和阻尼。
6. 距离黑线变小时降低透明度，最终看起来并入主线。

WebGL Canvas 透明且 `pointer-events: none`，不能阻挡链接和滚动。

## 性能预算

- 线束上限：12，每条最多 12 个节点；同一时间只有一对尾迹处于生长状态。
- DPR 上限：1.5。
- 每帧不写 React state。
- 不加载 3D 模型、HDR、阴影或后期处理。
- 摄影图片使用本地资源、合理尺寸与懒加载。
- 长帧时间被限制，避免切回标签页后模拟爆炸。

## 降级

- WebGL2 不可用：背景 SVG 线和完整内容仍然存在，只取消波纹。
- 减少动态效果：不生成连续波纹，隐藏线条回声，保留链接状态。
- 移动端：单指垂直滚动优先；只有明确拖动意图时产生少量反馈。

## 后续可扩展点

- 使用 transform feedback 或纹理存储将模拟移到 GPU。
- 为项目增加独立详情路由，同时保持视觉层在布局中持续存在。
- 用 CMS 替换静态内容前，先保持当前 DOM 结构和图片比例字段。
